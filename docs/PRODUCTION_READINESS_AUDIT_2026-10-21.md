- The supplied `admin`, `hod`, and `testap` logins succeeded and matched roles `admin`, `hod`, and `staff`. All three session cookies included `Secure` and `HttpOnly`; the sessions were logged out after the checks.
- The HOD task dashboard and department catalog returned 200. Admin user management returned 200. The admin document list returned 403, matching the current role policy. The CSE HOD complaint API and CSE staff student-management API returned 403 on this deployed version.
- The Render page response included HSTS, CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, and Permissions-Policy. This is a passive header check, not a full penetration test.
- No task, complaint, student, or staff record was created or edited. No AI API or AI workflow was invoked.

### Render metrics refresh (read-only, 2026-10-21 04:03 UTC)

- The service still uses the wrong GitHub repository, Free service plan, one instance, and an empty dashboard health-check path.
- The preceding 24-hour metrics query still shows instance churn; highest observed memory was 327,921,660 bytes (about 313 MiB), and CPU's raw peak was 0.0377 in Render's `cpu` unit. Series count reflects instance churn and should not be treated as simultaneous instance count.
- Render returned no `http_request_count`, `http_latency` p95, or instance-count samples. A production HTTP latency baseline remains unavailable.
- Event history confirms frequent automatic builds/deploys from new commits on `main`; the latest successful deploy in the inspected range was at 2026-10-20 18:17 UTC for commit `688aa6a495f3013bda575f3db885f05b9b5ac96e`.

- Passwords use Argon2 hashing; password inputs and account creation enforce length bounds.
- Session cookies are HTTP-only, production-secure, and `SameSite=Lax`; mutation routes use a CSRF token and same-origin checks.
- Upload parsing reads at most one byte over the configured 10 MB limit, checks known file signatures, and validates DOCX archive shape and expansion size.
- The student XLSX import checks archive structure, limits total expanded size to 8 MB, each member to 4 MB, worksheet dimensions to 101 rows by 4 columns, rejects macros/encryption, and refuses parsing unless openpyxl has `defusedxml` protections enabled. The local non-AI integration suite passed, including the existing student enrollment/import coverage.
- Private file downloads require resource authorization and return `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`.
- The app sets a restrictive Content Security Policy, frame denial, MIME sniffing protection, referrer policy, and production HSTS.
- Login failures are limited to 12 per source IP in a 15-minute window. Review retention/cleanup for the `login_failures` table as operational hardening.
- AI integration remains optional. The new deadline reminder path uses only the database-backed in-app inbox and does not call an AI provider, email, or SMS service.
- Oversight task summaries use grouped SQL aggregates rather than materializing every task and issuing one user query per staff member; HOD tracking ranks history in SQL and fetches at most 60 events, submissions, and decisions per visible task. Task date filters explicitly handle the maximum calendar date. The non-AI integration suite passed; production-sized load and query-plan measurements remain open.
- `/plot` now calculates navigation TTFB from navigation start, counts reported transfer bytes without substituting cached body sizes, and times out its health request after eight seconds. Chromium verified the live health probe, browser resource chart, privacy metadata, and four viewport widths on a local development server.
- `/healthz` uses `SELECT 1` to check database connectivity without scanning the user table. Render's dashboard health-check path remains blank until its source/deploy cutover.
- The worker now scans for deadline reminders every 15 minutes instead of every minute, processing at most 10 batches of 100 tasks per check. Delivery keys still enforce once-per-deadline or once-per-day behavior. Local integration coverage passed; throughput under a large overdue queue still needs load measurement.
- Case feeds and latest-message lookups now have composite indexes (`k11ncet015`). The full migration chain applied to a fresh temporary SQLite database and `alembic check` reported no drift. Production query plans and latency still need measurement.
- Roster branch labels are now resolved in one catalog query for the 1,000 displayed rows instead of one query per student. Local API and browser coverage passed. The API still caps each response at 1,000; server pagination and full export remain open work.
- Complaint date filters now bind UTC-aware boundaries, matching task filters and stored timestamps regardless of the host timezone. The non-AI integration suite passed.
- Project collaboration profile/feed/detail queries now batch profile and student-USN lookups and eager-load authors instead of issuing per-item queries. Local API and browser checks passed; query-count profiling with a large department dataset remains open.
- Project collaboration now stores a department snapshot per post; students, staff and HODs are filtered to their assigned branch for feeds, directories, profile lookup, discussion reads/comments, moderation and new-post alerts. HOD moderation is branch-bound. Migration `l12ncet016` backfills existing posts from their author's assigned branch and adds a department/time index. This is source-only and is not live until the migration is applied and the deployment is updated.

These controls are source observations, not proof of end-to-end security. Local authorization tests and mocked Chromium checks passed, Bandit passed, and the GitHub Security Audit (including `pip-audit -r requirements.txt`) and full CI both succeeded on the published commit. The limited live login/GET smoke passed for authentication and task access, but the deployed branch-specific complaint and student workspaces are still blocked for the CSE HOD/staff accounts. The full real-workflow simulation and externally scoped penetration test remain outstanding.

The custom domain `ncet.paladuguganeshnaidu.tech` still fails TLS negotiation on the current live check; its DNS resolves to Render, but the handshake failure prevents any secure login test.
